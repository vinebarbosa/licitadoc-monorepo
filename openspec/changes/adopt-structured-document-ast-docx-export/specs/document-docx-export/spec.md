## ADDED Requirements

### Requirement: Completed documents MUST be exportable as DOCX
The system MUST allow authorized actors to export completed documents as `.docx` files. The exported file MUST be generated by backend application code from structured document content, not returned directly by the AI provider.

#### Scenario: Authorized actor exports completed document
- **WHEN** an authenticated actor with visibility over a completed document requests DOCX export
- **THEN** the API returns a valid DOCX file generated from the document's structured content

#### Scenario: AI output is not used as DOCX file bytes
- **WHEN** a document was generated by an AI provider
- **THEN** the DOCX export is produced by the backend DOCX renderer from validated document content instead of using provider-returned binary or base64 file data

### Requirement: DOCX export MUST enforce document visibility and lifecycle rules
The DOCX export endpoint MUST reuse document read visibility rules and MUST only export documents that have completed content available.

#### Scenario: Organization-scoped actor exports another organization's document
- **WHEN** an authenticated `organization_owner` or `member` requests DOCX export for a document outside their organization
- **THEN** the system rejects the request

#### Scenario: Generating document cannot be exported
- **WHEN** an authenticated actor requests DOCX export for a document that is still `generating`
- **THEN** the system rejects the request instead of returning a partial DOCX file

#### Scenario: Failed or empty document cannot be exported
- **WHEN** an authenticated actor requests DOCX export for a failed document or completed document without content
- **THEN** the system rejects the request with an appropriate application error

### Requirement: DOCX export MUST preserve supported document semantics
The DOCX renderer MUST preserve supported AST semantics including headings, paragraphs, inline marks, lists, tables where supported, alignment, indentation, page breaks, placeholders, clauses, and signature blocks.

#### Scenario: Structured page break exports to DOCX page break
- **WHEN** a document AST contains a page break block
- **THEN** the exported DOCX contains a corresponding page break at that position

#### Scenario: Signature block exports with alignment
- **WHEN** a document AST contains a signature block with date, name, and role
- **THEN** the exported DOCX lays out those lines with the configured alignment rather than rendering Markdown artifacts

### Requirement: DOCX response MUST be a downloadable attachment
The DOCX export response MUST use the official DOCX MIME type and attachment disposition with a safe filename derived from document metadata.

#### Scenario: Export response headers identify DOCX attachment
- **WHEN** DOCX export succeeds
- **THEN** the response includes `application/vnd.openxmlformats-officedocument.wordprocessingml.document` as the content type
- **AND** the response includes an attachment filename ending in `.docx`

### Requirement: Preview DOCX action MUST download the exported file
The document preview page MUST enable the DOCX action only when export is available and MUST start a file download from the protected export endpoint when the action is used.

#### Scenario: Preview enables DOCX for completed document
- **WHEN** the preview page displays a completed document with exportable content
- **THEN** the `Exportar DOCX` action is enabled

#### Scenario: Preview downloads DOCX
- **WHEN** a user activates `Exportar DOCX` on an exportable document
- **THEN** the web app requests the protected DOCX export endpoint and starts a `.docx` download

#### Scenario: Preview disables DOCX for non-exportable document
- **WHEN** the preview page displays a generating, failed, inaccessible, or empty document
- **THEN** the `Exportar DOCX` action is disabled
